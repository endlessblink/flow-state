## 2025-05-14 - BaseDropdown ARIA Combobox Accessibility
**Learning:** Custom dropdown components that act like selects need to implement the standard W3C ARIA Combobox pattern (`role="combobox"`, `aria-activedescendant`, `aria-controls`) to be fully screen-reader accessible. Using random `Math.random()` string generations for element IDs (like `aria-controls`) can cause hydration mismatches or lack of true uniqueness, especially in SSR. Vue 3.5's `useId()` safely generates unique identifiers for such relational ARIA attributes. Also, explicitly applying `role="listbox"` on the popup and `role="option"` with `:aria-selected` bindings on the items ensures maximum assistive technology compatibility. Focus should remain on the trigger during navigation for `aria-activedescendant` to announce options correctly, therefore `@keydown` handlers must belong to the trigger, not the popup.
**Action:** Use `useId()` for generating IDs for all ARIA relationships (like `aria-controls`, `aria-describedby`, `aria-labelledby`, `aria-activedescendant`). Retain focus on the trigger and use `aria-activedescendant` whenever designing or updating custom dropdown or combobox components.
