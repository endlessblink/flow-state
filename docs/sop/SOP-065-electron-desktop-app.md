# SOP-065: FlowState Electron Desktop App — Setup, Build, Deploy

**Status**: Active
**Replaces**: SOP-011 (Tauri distribution)
**Last Updated**: 2026-03-25

---

## Architecture

```
electron/
├── main.ts          — Main process: window creation, IPC registration, updater
├── preload.ts       — Context bridge: exposes window.electronAPI to renderer
├── ipc/
│   ├── shell.ts     — shell.openExternal() for URLs, exec() for Docker/Supabase
│   ├── dialog.ts    — dialog.showSaveDialog() for backup export
│   ├── fs.ts        — Node.js fs via IPC (auth token files)
│   ├── store.ts     — JSON key-value store (replaces @tauri-apps/plugin-store)
│   ├── http.ts      — net.fetch in main process (CORS bypass for Ollama, iCal)
│   └── window.ts    — minimize, maximize, close
├── updater.ts       — Auto-updater via electron-updater
dist-electron/       — Compiled output (generated)
electron-builder.yml — Packaging config
```

**Key generated file**: `dist-electron/package.json` with `{"type":"commonjs"}` — generated by `electron:build-main` script because root `package.json` has `"type":"module"`. This is intentional; do not delete it.

## Platform Detection

**`src/utils/platform.ts`** is the source of truth:

```typescript
export function isElectron(): boolean {
  return typeof window !== 'undefined' && !!window.electronAPI
}

export function isTauri(): boolean {
  return false  // Tauri removed — always false
}
```

- `window.electronAPI` is injected by `electron/preload.ts` via `contextBridge.exposeInMainWorld`
- All `@tauri-apps/*` imports are stubbed via the `tauri-stub` Vite plugin in `vite.config.ts`
- Dead code paths behind `isTauri() === false` are tree-shaken in production

## Development

**Two-terminal workflow:**

```bash
# Terminal 1: Start Vite dev server
npm run dev           # Serves on http://localhost:5546

# Terminal 2: Launch Electron (connects to Vite)
npm run electron:dev  # Requires dev server running first!
```

**One-command preview (production build):**

```bash
npm run electron:preview   # Builds + runs production Electron
```

**Note**: `electron:dev` WILL fail if Vite isn't running on port 5546 first.

## Production Build

```bash
# Step 1: Build Vue app with Electron mode flag
ELECTRON_BUILD=true npm run build

# Step 2: Compile Electron main process (TypeScript → CommonJS)
npm run electron:build-main

# Step 3: Package with electron-builder
npx electron-builder --config electron-builder.yml --linux
```

**Output**: `release/linux-unpacked/flowstate` (runnable) + `release/*.AppImage` (distributable)

### electron-builder.yml Key Settings

- `npmRebuild: false` — Skip native module rebuild (not needed)
- Linux target: `AppImage` (self-updating format — .deb cannot auto-update)
- `productName: FlowState`, `executableName: flowstate`

## Local Install

After building, the app can be installed for the current user without root:

**Wrapper script** at `~/.local/bin/flowstate`:
```bash
#!/bin/bash
exec /path/to/release/linux-unpacked/flowstate --no-sandbox --class=flow-state "$@"
```

**Desktop entry** at `~/.local/share/applications/flowstate.desktop`:
```ini
[Desktop Entry]
Name=FlowState
Exec=flowstate %U
Icon=flowstate
Type=Application
Categories=Productivity;
StartupWMClass=flow-state
```

**Icon**: Copy `release/linux-unpacked/resources/app.asar.unpacked/...` or source icon to
`~/.local/share/icons/hicolor/512x512/apps/flowstate.png`

After updating the .desktop file: `update-desktop-database ~/.local/share/applications/`

## KDE Dock Integration

**WM_CLASS** must be `flow-state` (lowercase with hyphen) for KDE to match the running window to the pinned dock entry.

This is set two ways:
1. `app.setName('flow-state')` in `electron/main.ts` (sets the app name used by Electron for WM_CLASS)
2. `--class=flow-state` flag in the `~/.local/bin/flowstate` wrapper script (belt and suspenders)

**`StartupWMClass` in .desktop must match exactly**: `flow-state`

**To pin to dock**: Launch the app → right-click the dock icon → "Pin to Task Manager"

## Deploy to VPS

```bash
./scripts/deploy-electron-update.sh --notes "TASK-XXX: description"
```

**What it does**:
1. Validates environment (VPS_HOST, SITE_URL)
2. Uploads AppImage to VPS at `/var/www/flowstate/updates/electron/`
3. Uploads `latest-linux.yml` (auto-generated by electron-builder)
4. Verifies the upload

**Environment** (hardcoded in the `electron` skill, or set manually):
```bash
VPS_HOST=84.46.253.137
SITE_URL=https://in-theflow.com
VPS_USER=root
```

**Update endpoint**: `https://in-theflow.com/updates/electron/latest-linux.yml`

**Version bump**: Only `package.json` — no Cargo.toml, no tauri.conf.json (Electron has no Rust).

## Auto-Updater

**`electron/updater.ts`** uses `electron-updater` package:
- Checks for updates on app launch (with delay)
- Downloads update in background
- Shows toast notification with "Download" / "Install" action
- Update feed URL: derived from `publish.url` in `electron-builder.yml`

**No signing key required** for Linux AppImage auto-updates (unlike Tauri which required a `.key` file).

---

## Session Persistence

- Electron persists `localStorage` to `~/.config/flow-state/` (derived from `package.json` `name` field)
- Auth sessions survive app restarts
- This path is **separate** from browser localStorage (different origin: `file://` vs `https://`)
- The `name` field in `package.json` is `flow-state` — changing it would break existing user sessions

## Version Bump Protocol

Only one file needs updating (no Cargo.toml, no tauri.conf.json):

```bash
npm version patch --no-git-tag-version   # bumps package.json only
# or edit package.json "version" field manually
```

Then commit:
```bash
git add package.json
git commit -m "chore: v{VERSION} — {description}"
```

## Known Issues / Gotchas

| Issue | Cause | Resolution |
|-------|-------|------------|
| ERR_FILE_NOT_FOUND in running Electron production instance | `npm run build` regenerates dist/ with new chunk hashes | Restart the Electron app after building |
| `electron:dev` fails immediately | Dev server not running on port 5546 | Start `npm run dev` first |
| GTK module warnings on launch | Harmless GTK environment noise | Ignore |
| LIBDBUSMENU warnings | D-Bus menu integration (non-fatal) | Ignore |
| APPIMAGE warnings | AppImage runtime environment | Ignore |
| `better-sqlite3` excluded from bundle | `npmRebuild: false` + excluded in config | Intentional — not needed in renderer |
| `@tauri-apps/*` import errors in build | Should be stubbed by tauri-stub Vite plugin | Check `vite.config.ts` alias config |
| WM_CLASS mismatch in KDE dock | app.setName() or --class flag missing | Verify both are set to `flow-state` |
